## 0. 폴더 꾸리기 (52단계)

```text
[작업 폴더 이름. 예: Cowork_주간보고_0310]
├── 재료/      원본의 복사본, 양식, 참고 자료. 읽기만 한다
├── 결과/      Claude가 만든 모든 파일. 여기에만 만든다
└── 안내.txt   목적, 이름 규칙, 읽는 사람
```

- [ ] 재료에 넣은 파일이 모두 복사본이고, 원본은 제자리에 있다
- [ ] 이번 일과 상관없는 파일이 폴더에 없다
- [ ] 폴더 전체의 사본을 [위치]에 [날짜]를 붙여 따로 두었다(파일을 옮기거나 이름을 바꾸는 일일 때)

## 1. 안내.txt (세 줄, 필요하면 금지 한 줄)

```text
목적: [이 폴더에서 무엇을 만드는지 한 문장]
이름 규칙: 결과 파일은 [날짜_내용] 형식. 예) 0310_주간보고.docx
읽는 사람: [누가 읽는지, 무엇을 모른다고 볼지]
금지: 재료 폴더의 파일은 고치지 않는다.
```

## 2. 첫 지시: 무엇이 있는지 먼저 말해 (52단계)

```text
오늘은 이 폴더에서 작업한다.
먼저 안내.txt를 읽고, 재료 폴더에 무엇이 있는지 목록으로 알려 줘.
아직 아무것도 만들거나 고치지 마.

규칙:
- 재료 폴더의 파일은 읽기만 한다. 고치거나 지우거나 옮기지 않는다.
- 새로 만드는 파일은 모두 결과 폴더에 저장한다.
- 파일 이름은 [날짜_내용] 형식으로 붙인다.
- 이 폴더 밖의 파일은 읽지도 고치지도 않는다.

목록에는 파일 이름, 종류, 간단한 내용 설명을 적어 줘.
안내.txt의 목적을 네 말로 한 문장으로 다시 설명해 줘.
```

- [ ] 받은 목록의 파일 수가 재료 폴더와 같다
- [ ] Claude가 설명한 목적이 내 뜻과 같다. 다르면 그 부분만 바로잡았다
- [ ] 결과 폴더가 아직 비어 있다

## 3. 본 지시

```text
할 일: [한 가지 일만. 예: 재료 폴더의 방문 기록으로 이번 주 영업 주간 보고를 만든다]
읽는 사람과 쓰임새: [예: 본부장이 월요일 회의 전에 한 번 읽고 다음 행동을 정한다]
쓸 재료: [파일 이름. 예: 재료/영업_방문기록.csv]
쓸 스킬이나 양식: [있으면 이름]

끝의 모양 (이것을 보면 끝났다고 본다):
- [예: 결과 폴더에 docx 파일 하나. 안에 요약 한 단락, 거래처별 표 하나]
- [예: 원본의 거래처 수와 결과의 거래처 수가 같다. 구분 기준은 거래처코드]
- [예: 빈칸이 있으면 "확인 필요"로 표시돼 있다]

반드시 지킬 것:
- 파일을 지우지 않는다. 필요 없어 보이는 파일은 후보로만 적는다.
- 같은 이름의 파일이 있으면 덮어쓰지 않는다. 이름 끝에 구분 표시를 붙인다.
- 이 폴더 밖의 파일은 읽지도 고치지도 않는다.
- 이름 바꾸기와 옮기기는 실행 전에 "지금 이름 → 바꿀 이름" 목록을 먼저 보여 주고, 내가 좋다고 한 뒤에만 한다.
- 메일 발송, 게시, 제출은 하지 않는다. 초안까지만 만든다.

멈추고 물을 것:
- [예: 거래처코드가 없는 기록이 있으면 만들기 전에 묻는다]
- [예: 금액이 원본끼리 맞지 않으면 계산하지 말고 묻는다]

하지 않을 것:
- [예: 금액을 새로 계산하지 않는다. 적힌 그대로 옮긴다]

중간에 내가 "멈춰"라고 하면 바로 멈추고, 그때까지 바꾼 것의 목록을 보여 줘.
```

## 4. 끝났다는 보고를 받은 뒤 (58단계)

먼저 결과 폴더를 직접 연다. 요약은 결과물이 아니다.

- [ ] 있는가: 파일이 결과 폴더에 있고 제대로 열린다
- [ ] 개수가 맞는가: 원본과 결과의 항목 수가 같다
- [ ] 합계가 맞는가: 합계 하나를 원본에서 직접 더해 비교했다
- [ ] 처음과 끝이 들어갔는가: 목록의 첫 항목과 마지막 항목이 있다
- [ ] 빈칸이 있는가: 빈칸마다 이유가 적혀 있다
- [ ] 재료 폴더의 파일 수와 수정 날짜가 맡기기 전과 같다

그다음 자기 점검을 받아 내 확인과 맞대어 본다.

```text
방금 끝낸 일을 스스로 점검해 줘. 새로 고치지는 말고 점검만 해.

처음 지시에 적은 끝의 모양:
- [끝의 모양 1]
- [끝의 모양 2]
- [끝의 모양 3]

항목마다 표로 답해 줘. 열: 항목 / 확인한 방법 / 결과(맞음·틀림·확인 못 함) / 근거(숫자가 있으면 숫자로)
"확인 못 함"이 있으면 왜 못 했는지 적어.
작업 중에 읽지 못한 파일이나 건너뛴 단계가 있었다면 따로 적어.
```

## 5. 잘못됐을 때 (59단계)

1. 멈추게 한다: "지금 하던 일을 멈춰."
2. 바뀐 것의 목록을 받는다: 지운 것, 이름을 바꾼 것, 덮어쓴 것.
3. 복사해 둔 원본에서 되살린다.
4. 이번 사고를 막았을 문장 하나를 다음 지시의 "반드시 지킬 것"에 더한다.
