# 복사해 쓰는 프롬프트 146개

본문의 「복사해 쓰는 프롬프트」를 단계 순서대로 모았습니다. 대괄호 `[ ]` 안만 바꿔 넣으면 됩니다.

### 1단계 · Claude는 검색창이 아니다

```text
나는 [회사/부서]에서 [직책]을 맡고 있다.
이번 주에 [해야 할 일]을 끝내야 한다.
이 결과물은 [읽을 사람]이 [목적]을 위해 읽는다.
[원하는 형식: 한 페이지 요약 / 표 / 목록 등]으로 초안을 써 달라.
내가 알려 주지 않은 회사 사정은 추측하지 말고 모른다고 표시해 달라.
```

### 2단계 · 첫 대화, 그리고 내 계정과 모델 고르기

```text
나는 [직무]다. 오늘 네가 도울 수 있는 일을 내 업무 기준으로 다섯 가지 말해 달라.
각각 어떤 자료를 주면 좋은지, 사람이 반드시 확인할 부분은 무엇인지 함께 적어 달라.
```

### 3단계 · 파일과 이미지 건네기

```text
첨부한 [문서 이름]만 근거로 답하라.
문서에 없는 내용은 추측하지 말고 "문서에 없음"이라고 적어라.

할 일: [요약 / 조건 정리 / 비교 등]
읽을 사람: [누구]
형식: 항목별 목록. 각 항목 끝에 문서 안의 위치(쪽, 조항, 시트 이름 등)를 괄호로 적는다.
일반적으로는 있을 법하지만 이 문서에는 없는 항목이 있으면 맨 끝에 따로 모은다.
```

### 4단계 · 웹 검색과 출처 확인

```text
웹 검색으로 [주제]의 최근 동향을 조사하라.
기간: [최근 몇 개월 / 올해 등]

출처 기준:
- 공식 발표, 정부·공공기관 자료, 주요 언론을 우선한다.
- 개인 블로그나 출처가 불분명한 글은 쓰지 않거나, 쓰면 따로 표시한다.

형식:
- 사실마다 출처 링크와 발표 날짜를 붙인다.
- 출처끼리 말이 다르면 합치지 말고 나란히 적는다.
- 마지막에 "확인이 더 필요한 것"을 따로 모은다.
```

### 5단계 · 같은 설명은 프로젝트에, 나에 대한 것은 메모리에

```text
[프로젝트 지침]
이 프로젝트는 [업무 이름]을 위한 것이다.
나는 [회사/부서]의 [직책]이다.
결과물을 읽는 사람은 [누구]이고, [목적]으로 읽는다.

규칙:
- 결론을 첫 문장에 쓴다.
- 분량은 [한 페이지 / 목록 몇 항목 등]을 넘기지 않는다.
- 말투는 [보고서체 / 메일체 등]으로 한다.
- 지식에 올린 [견본 파일 이름]과 같은 형식으로 쓴다.
- 숫자와 사실은 올린 자료에 있는 것만 쓴다. 없으면 "확인 필요"라고 적는다.
- 모르는 것이 있으면 쓰기 전에 먼저 묻는다.
```

### 6단계 · 틀린 답을 알아보는 법

```text
방금 답에 나온 숫자, 날짜, 고유명사, 인용문을 모두 표로 뽑아라.

열: 항목 / 답에 나온 값 / 출처(올린 자료의 위치, 또는 링크) / 확실한 정도(확인됨·추정·출처 없음)

출처가 없거나 추정인 항목은 본문에서 "확인 필요"로 바꾼 수정본도 함께 달라.
```

### 7단계 · 회사 자료를 지키는 원칙

```text
아래 문서를 외부 AI 도구에 올려도 되는지 점검하려 한다.
문서 내용은 가공한 샘플이다.

다음을 찾아 목록으로 표시하라:
- 사람을 알아볼 수 있는 정보(이름, 연락처, 주민번호, 주소 등)
- 회사나 거래처를 알아볼 수 있는 정보
- 금액, 계약 조건 등 민감할 수 있는 수치
- 이름이 없어도 날짜·장소·직급 같은 문맥으로 누구인지 드러나는 곳
각 항목마다 [삭제 / 가명 처리 / 그대로 둠] 가운데 무엇을 권하는지 적어라.

[문서 붙여 넣기]
```

### 8단계 · 다섯 칸 질문 틀

```text
[누구로서] 너는 [회사 종류]의 [직책]이다.

[왜] 이 결과물은 [누가] 읽는다. 필요한 이유는 [왜]. 지금까지 상황은 [배경 한두 문장].

[무엇을] [해 달라는 일 하나를 동사로 끝낸다].

[어디까지]
- [지켜야 할 것]
- [하지 말아야 할 것]
- 내가 준 자료에 없는 사실은 만들지 말고, 모르면 모른다고 적어 줘.

[어떤 형식으로] [표/목록/문단], [분량], [말투].
```

```text
아래 요청에 답하지 말고, 다섯 항목(누구로서·왜·무엇을·어디까지·어떤 형식으로)으로 나눠 다시 써줘.
내가 적지 않은 항목은 채우지 말고 "[비어 있음: 무엇을 적어야 하는지]"로 남겨줘.
답에 가장 큰 차이를 만들 빈 항목부터 알려줘.

[내 짧은 요청]
```

### 9단계 · 맥락과 본보기를 건네고, 모르면 되묻게 하기

```text
이 글을 읽는 사람은 [누구]다. 그 사람들은 [무엇을 이미 알고 / 무엇을 모른다].
이 글이 필요한 이유는 [왜]다. 읽고 나서 그 사람들이 [무엇을 하기]를 바란다.
지금까지의 사정: [지난번에 있었던 일, 피해야 할 것].
첨부한 [자료 이름]이 기준이다. 나머지는 참고만 하고, 어긋나면 기준 자료를 따른다.

아래 예시는 우리 팀이 좋다고 판단한 [글 종류]다. 형식, 말투, 문장 길이, 단락 나누는 법만 따르고 내용은 따르지 마라.
<예시>
[개인정보를 지운 예시 글]
</예시>

위 조건으로 [해 달라는 일]을 해줘. 예시와 달라진 부분이 있다면 끝에 한 문장으로 알려줘.
```

```text
아래 예시 글들의 공통된 말투와 형식을 규칙 다섯 가지로 뽑아줘. 내용은 요약하지 말고 쓰는 방식만 적어줘. 나중에 이 규칙을 프로젝트 지침에 넣을 것이다.

<예시1>
[예시 글]
</예시1>
<예시2>
[예시 글]
</예시2>
```

```text
바로 시작하지 말고, 이 일을 잘하려면 나에게 확인해야 할 것을 먼저 물어봐.
- 결과를 가장 크게 바꾸는 질문만 세 개 이내로 골라줘.
- 가능하면 내가 고르기만 하면 되는 선택지 형태로 물어줘.
- 질문마다 네가 추천하는 기본값을 함께 적어줘.
- 내가 답하면 그때 시작해.
```

```text
모르는 것이 있어도 멈추지 말고 합리적으로 가정해서 진행해줘.
다만 결과 맨 위에 "가정한 것" 목록을 따로 적어줘. 내가 그 목록만 보고 틀린 가정을 고칠 수 있게.
```

### 10단계 · 형식을 정하고 근거부터 받기

```text
[결정할 일]에 대해 판단을 도와줘. 결론은 맨 마지막에 쓰고, 그 전에 아래 순서로 따져줘.

1. 이 판단에 쓸 기준을 먼저 정해줘. 기준마다 왜 따져야 하는지 한 문장씩.
2. 기준별로 [안 A]와 [안 B]를 비교해줘.
3. 비교 가운데 내가 준 자료로 확인된 것과 네가 추정한 것을 나눠 표시해줘.
4. 판단을 뒤집을 수 있는 조건이 있다면 적어줘.
5. 마지막에 추천과 그 이유를 세 문장 안으로.

형식:
- 모양: [표 / 번호 목록 / 문단]. 표라면 열은 [열 이름들], 단위는 [단위].
- 분량: [한 페이지 / 항목당 한 문장 등]. 분량과 내용이 부딪치면 [분량 / 내용]을 먼저 지켜줘.
- 말투: [보고체 / 고객 존댓말 / 사내 메신저체].
- 형식 외의 인사말이나 덧붙이는 설명은 쓰지 마.

참고 자료: [자료 또는 사실관계]
```

```text
방금 판단에서 [기준 이름]은 우리 사정과 다르다. 실제로는 [우리 사정]이다.
이 기준만 다시 평가하고, 결론이 바뀌는지와 그 이유를 적어줘. 다른 기준의 평가는 그대로 둬.
```

### 11단계 · 고쳐 쓰기 대화

```text
방금 결과를 고쳐줘. 처음부터 다시 쓰지 말고 아래만 바꿔.

그대로 둘 것:
- [잘된 부분]

고칠 것:
- [위치]: [무엇이 문제인지, 왜] → [어떻게 바꿀지]
- [위치]: [무엇이 문제인지, 왜] → [어떻게 바꿀지]

고친 뒤 바뀐 부분만 따로 표시해줘. 고치라고 하지 않은 숫자나 이름, 단위는 바꾸지 마.
```

```text
이 대화에서 여러 번 고치며 정한 조건을 새 대화에서 쓸 요청문 하나로 정리해줘.
- 처음 요청과 이후 고침 지시를 모두 반영해.
- 서로 부딪친 지시가 있으면 나중 지시를 따르고, 부딪친 곳을 따로 알려줘.
- 요청문은 다섯 항목(누구로서·왜·무엇을·어디까지·어떤 형식으로)으로.
```

### 12단계 · 긴 문서 다루기

```text
첨부한 문서의 뼈대를 먼저 잡아줘.
- 장이나 절 단위로 나눠 각각 두세 문장으로 요약해줘.
- 끝에, 처음 읽는 사람이 특히 주의해서 볼 곳을 알려줘.
아직 결론이나 의견은 쓰지 마.
```

```text
같은 문서에 대해 질문한다. 답마다 근거가 된 원문을 따옴표로 그대로 옮기고, 어느 장인지 적어줘.
문서에 근거가 없으면 추측하지 말고 "문서에 없음"이라고 적어줘.

질문:
1. [질문]
2. [질문]
```

```text
방금 목록에서 [항목]의 인용이 원문과 다르다. 원문은 다음과 같다.
"[원문]"
이 항목을 고치고, 목록 전체에서 같은 종류의 내용(날짜, 기준일, 금액)이 나오는 항목을 원문과 다시 대조해줘.
```

### 13단계 · 내 업무 프롬프트 다섯 개

```text
[프로젝트 지침 초안]

나는 [회사 종류]의 [직책]이고, 주로 [업무 범위]를 맡는다.
내가 쓰는 결과물은 주로 [누가] 읽는다.

모든 대화에서 다음을 지켜줘.
- 시작 전에 결과를 크게 바꿀 확인 사항이 있으면 세 개 이내로 먼저 물어봐.
- 내가 준 자료에 없는 사실이나 숫자는 만들지 말고, 모르면 모른다고 적어.
- 추정한 내용은 (추정)이라고 표시해.
- 결론을 먼저 쓰고 근거를 뒤에 붙여.
- 말투는 [보고체 / 사내 메신저체], 불필요한 인사말은 빼.
- 메일 발송, 삭제처럼 밖으로 나가거나 되돌릴 수 없는 일은 초안까지만 만들고 내 확인을 받아.
```

```text
[업무 프롬프트 틀: 다섯 개를 이 형식으로 만든다]

업무 이름: [예: 주간 회의 안건 정리]
언제 쓰나: [예: 매주 월요일 오전, 회의 전]

[누구로서] (지침에 있으면 생략. 이 업무만 다르면 적는다)
[왜] 이번 건은 [상황 한두 문장]. 읽는 사람은 [누구].
[무엇을] 첨부한 [자료]로 [해 달라는 일].
[어디까지] [이 업무만의 조건].
[어떤 형식으로] [모양, 분량, 순서].
```

### 14단계 · 대화와 결과물을 나누는 그릇, 아티팩트

```text
[결과물 이름]을 만들려고 한다. 읽는 사람은 [누구]이고 최종적으로 [워드/엑셀/파워포인트/웹페이지]로 쓸 것이다.

지금은 아티팩트로 초안을 띄워 줘. 내가 몇 번 고친 뒤 "파일로 줘"라고 하면 그때 [파일 형식]으로 만들어 줘.
고칠 때는 내가 지적한 곳만 바꾸고 나머지는 그대로 둬.
```

### 15단계 · 결재에 바로 올리는 문서와 살아 있는 스프레드시트

```text
너는 중견 유통사 운영본부의 기획 담당이다.
읽는 사람: 대표이사
이 보고서로 결정할 것: 물류센터를 내년 상반기에 옮길지, 한 해 미룰지
첨부 자료만 근거로 두 쪽 안팎의 보고서를 워드 파일로 만들어 줘.
첫 쪽 맨 위에 결론과 요청 사항을 먼저 쓰고, 선택지는 표로 비교해 줘.
자료에 없는 사실은 [확인 필요]로 표시해 줘.
```

```text
너는 [회사 업종] 회사의 [부서] 보고서 작성자다.

읽는 사람: [직책]
이 보고서로 결정할 것: [결정 사항]
첨부한 자료: [자료 이름과 짧은 설명]
회사 양식: [첨부했으면 "첨부한 양식의 목차와 제목 순서를 따른다", 없으면 비운다]

위 자료만 근거로 [보고서 종류] 초안을 워드 파일로 만들어 줘.
- 첫 쪽에 결론과 요청 사항을 먼저 쓴다
- 선택지나 비교가 있으면 표로 정리한다
- 분량: [쪽 수]. 말투: 평서체, 짧은 문장
- 첨부 자료에 없는 사실은 지어내지 말고 [확인 필요]로 표시하고, 파일 끝에 목록으로 모은다
시작하기 전에 모르는 것이 있으면 먼저 물어봐.
```

```text
[표의 목적]을 위한 엑셀 파일을 만들어 줘.

쓰는 사람: [누가, 얼마나 자주]

조건
- 합계·비율·곱셈은 숫자를 직접 적지 말고 엑셀 수식으로 넣는다
- 행을 더 넣어도 합계에 들어가도록 범위를 잡는다
- 입력 셀과 계산 셀은 배경색으로 구분하고, 맨 위에 목적과 사용법을 두 줄로 적는다
- 별도 시트에 사용한 수식을 셀별로 설명한다
- 입력값 하나를 바꿨을 때 어느 셀이 얼마로 바뀌어야 하는지 검산용 예를 하나 알려 줘
```

```text
- 출처끼리 말이 다르면 둘 다 적고 어긋난다고 표시한다.
- 조사를 시작하기 전에 계획(볼 자료의 순서, 표의 열 구성)을 먼저 보여 주고, 내가 좋다고 하면 진행한다.

결과물: 결과 폴더에 [파일 형식: docx 등]으로 저장.
순서: 결론 한 단락 → 근거 표 → 출처 목록 → 더 알아볼 것
다 끝나면 "확인 필요" 항목이 몇 개이고 어디인지 알려 줘.
```

### 58단계 · 데이터 분석가로 쓰기

```text
너는 우리 팀의 데이터 분석가다.

질문: [예: 지점별로 지난 분기 대비 이번 분기 매출이 줄어든 곳은 어디인가]
재료: 재료 폴더의 엑셀 파일 전부

순서:
1. 파일마다 시트 구조, 머리글, 단위, 기간, 합계 행 위치를 읽고 서로 다른 점을 표로 보고해. 아직 합치지 마.
2. 내가 머리글 대응과 단위를 정해 주면 그대로 하나의 표로 합쳐.
3. 질문에 답하는 비교표 하나와 차트 하나를 만들어. 질문과 상관없는 분석은 더하지 않는다.

규칙:
- 재료 폴더의 파일은 고치지 않는다.
- 결과 엑셀에는 수식을 살려 두고, 계산 과정을 별도 시트에 정리한다.
- 원인에 대한 추측은 "추측"이라고 표시하고 따로 적는다.

결과물: 결과 폴더에 [파일 이름].xlsx 하나로 저장.
다 끝나면 전체 합계와 파일별 합계를 알려 줘. 내가 원본과 맞춰 볼 거야.
```

### 59단계 · 보고서 작성자로 쓰기

```text
메모: 재료 폴더의 나머지 파일 전부

할 일:
- 양식의 항목 구성과 순서를 그대로 둔다. 항목을 더하거나 빼지 않는다.
- 각 항목에 해당하는 내용을 메모에서 찾아 채운다.
- 항목마다 끝에 [출처: 메모 파일 이름]을 괄호로 적는다.
- 메모에 없는 내용은 지어내지 않는다. 그 항목은 비워 두고 "메모 없음"이라고 쓴다.
- 특히 계획, 수치, 이슈 항목은 메모에 적힌 것만 옮긴다. 추정하지 않는다.

말투: [예: 보고받는 사람은 팀장. 짧은 평서문, 한 항목에 서너 줄 이내]
결과물: 결과 폴더에 [날짜]_주간보고.[docx 등]로 저장.
다 만들면 "메모 없음" 항목이 어디인지, 읽지 못한 메모 파일이 있는지 목록으로 알려 줘.
```

### 60단계 · 편집자·검토자와 프로젝트 매니저로 쓰기

```text

검토할 글: 재료 폴더의 [파일 이름]
참고할 글: [이전 글·용어집 파일 이름, 없으면 없음]
읽는 사람: [예: 현장 직원, 처음 읽는 거래처]

결과는 표로 줘. 열: 번호 / 위치(몇째 단락) / 원문 / 문제 / 제안 / 심각도(높음·중간·낮음)

원본 파일은 수정하지 않는다.
내가 받아들일 번호를 고르면, 그 항목만 반영한 새 파일을 결과 폴더에 만든다.

```

```text
너는 이 프로젝트의 매니저다.

재료: 재료 폴더의 [이번 회의록 파일], [지난 할 일 표 파일, 없으면 없음]

할 일:
1. 회의록에서 결정 사항과 할 일을 나눈다.
2. 할 일은 담당자 이름이 나온 것만 표로 만든다. 열: 할 일 / 담당 / 기한 / 회의록 근거 문장
3. 할 일로 보이지만 담당이 분명하지 않은 것은 "담당 불분명" 표에 따로 모은다.
4. 기한이 없으면 비워 두고 "기한 없음"이라고 쓴다. 기한을 추측하지 않는다.
5. "한번 보죠"처럼 약속인지 애매한 말은 할 일로 넣지 않고 "논의만 함"에 적는다.
6. 지난 표가 있으면 끝난 것 / 이어지는 것 / 새로 생긴 것으로 나누고, 두 번 이상 이어진 일을 표시한다.

결과물: 결과 폴더에 [날짜]_할일.xlsx로 저장.
참석자에게 보낼 메일 초안도 따로 써 줘. 메일은 보내지 않는다.
```

### 62단계 · 권한과 되돌리기


### 81단계 · 경영: 월간 보고를 상시 의사결정으로

### 82단계 · 전략: 조사를 가설 검증 루프로

```text
- 회사별로: 제품, 가격·판촉, 유통, 조직·투자 네 항목

- 출처를 찾지 못한 내용은 쓰지 않고 "확인하지 못한 것"으로 보낸다.
- 우리 회사가 할 일은 쓰지 않는다.
- 지난 분기 보고서와 같은 순서로 쓴다.

결과는 [docx] 파일로 작업 폴더에 저장해 줘.
```

### 83단계 · 영업: 고객 정보가 쌓이는 영업 흐름

```text
- 말투는 [정중하되 짧게].
```
