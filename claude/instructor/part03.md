# 제3부 · Claude Code로 직접 만들기 — 강사용 안내

## 이 부의 목표
- 코드를 쓰지 않고도 Claude Code에게 일을 맡기고, 계획을 읽고, 결과를 직접 눌러 보고, 틀리면 되돌리는 흐름을 몸에 익힌다.
- 업무 파일 정리(합치기, 보고서 초안, 반복 파일 작업)를 원본 보호와 검산 습관과 함께 해 본다.
- 사내 도구 하나를 설치부터 GitHub 저장소, 커밋과 되돌리기, 배포까지 진행해 동료의 휴대폰에서 열리는 주소를 받는다.
- 배포가 멈추는 곳, 인증키와 권한 같은 안전장치, 훅·서브에이전트·MCP의 쓰임새를 알고, 완료 보고를 검증한 뒤 발표하고 넘긴다.

## 꼭 보여 줄 시연
1. **폴더를 잘못 잡고 켠 Claude Code (25단계).** 홈 폴더에서 `claude`를 켜고 "이 폴더에 무엇이 있는지 알려 줘"를 친 뒤, `/exit`로 나와 `cd`로 작업 폴더에 들어가 다시 켠다. 청중은 같은 질문에 문서·다운로드 목록과 빈 폴더라는 답이 각각 돌아오는 차이를 본다.
2. **계획에서 걸리는 항목 찾기 (26단계).** 여러 파일에 걸친 기능을 계획만 요청하고, 목적·파일 목록·지우기와 덮어쓰기 세 가지를 화면에서 표시한 뒤 한 곳을 되물어 고쳐진 계획을 받는다. 청중은 실행 전에 묻는 쪽이 훨씬 싸다는 점과, 계획을 읽는 데 코드 지식이 필요 없다는 점을 확인한다.
3. **검산으로 드러나는 누락 (27단계).** 머리글이 4행에 있는 CSV를 섞어 합치게 한 뒤 건수 검산을 시킨다. 청중은 "완료했습니다" 보고와 실제 건수가 다를 수 있다는 것, 합계 하나는 원본을 직접 열어 맞춰야 한다는 것을 본다.
4. **일부러 망가뜨리고 되돌리기 (29단계).** 제목을 이상한 문장으로 바꿔 커밋하고 푸시한 뒤 그 커밋만 되돌린다. 청중은 GitHub 커밋 목록에 망가뜨린 기록과 되돌린 기록이 나란히 남고, 다른 변경은 그대로 살아 있는 것을 본다.
5. **푸시에서 주소까지 (30·31단계).** 문구 하나를 고쳐 푸시하고 배포 목록에서 "만드는 중"이 "준비됨"으로 바뀌는 것을 보여 준 뒤, 청중에게 주소를 열게 한다. 예전 화면이 보이는 사람이 있으면 시크릿 창으로 열게 해서 캐시 문제를 그대로 보여 준다.

## 과제 채점 기준
| 항목 | 통과 기준 | 자주 보는 실수 |
|---|---|---|
| 배포된 주소 | 평가자가 자기 휴대폰으로 본줄 기준의 본 주소를 열고, 가장 중요한 동작을 도움 없이 끝까지 해 본다 | 미리보기 주소를 제출한다. 노트북에서만 확인해 휴대폰에서 기록이 남지 않는다 |
| GitHub 저장소와 커밋 기록 | 비공개 저장소에 평가자 읽기 권한이 있고, 한 가지씩 나뉜 우리말 커밋 메시지와 일부러 깨뜨렸다가 되돌린 기록이 하나 이상 있다 | "Update index.html" 같은 메시지 하나에 여러 변경이 섞여 있다. 되돌리기를 해 보지 않았다 |
| 푸시 후 반영 시연 | 평가자 앞에서 문구 하나를 고쳐 푸시하면 같은 주소에 반영된다 | 다른 브랜치에 머물러 있어 본 주소가 바뀌지 않는다 |
| CLAUDE.md | 저장소 맨 위에 있고, 이 폴더가 무엇인지, 규칙, 하지 말 것, 끝났다고 말하기 전에 할 확인이 확인할 수 있는 문장으로 들어 있다 | "개인정보 조심", "깔끔하게" 같은 흐린 규칙이 남아 있다. `/init` 초안을 고치지 않고 냈다 |
| 안전 | 저장소, 커밋 기록, 화면 코드 어디에도 인증키·비밀번호·실제 고객 정보가 없다. 키를 쓰는 도구는 환경변수로 읽는다 | 키를 화면 코드에서 바로 읽는다. 올렸던 키를 지우기만 하고 폐기하지 않았다 |
| 핵심 프롬프트 세 개 | 처음 만들 때, 가장 중요한 기능을 붙일 때, 검증할 때 쓴 프롬프트가 각각 있다 | 검증 프롬프트가 "잘 되는지 확인해 줘" 수준이다 |
| 업무 파일 정리 결과 | 합친 표나 보고서 초안이 있고, 원본 파일이 바뀌지 않았으며, 합친 표의 건수가 원본 합과 같다는 검산 기록이 있다 | 원본 폴더에서 바로 작업했다. 합계를 Claude에게만 확인시켰다 |
| 한 쪽짜리 메모 | 도구 설명 한 문장, 되돌리거나 막혔던 일 하나와 푼 방법, 훅으로 옮길 규칙 후보 하나와 그 이유가 들어 있다 | 훅 후보로 되돌릴 수 있는 규칙(색, 문구)을 골랐다 |
| 이어받기 | 평가자가 CLAUDE.md와 커밋 기록만 보고 무엇을 어떻게 고칠지 말할 수 있다 | 규칙은 있지만 확인 방법이 빠져 있어 다음 사람이 같은 확인을 할 수 없다 |

**3단계 평가**
- **우수:** 모든 항목을 통과했고, 평가자가 휴대폰에서 동작을 해 보는 동안 막힘이 없다. 메모의 훅 후보가 어기면 되돌릴 수 없는 규칙이며, 실제로 훅 계획을 받아 보았거나 일부러 어겨 시험한 기록이 있다. 인수인계 뒤 다른 사람이 도움 없이 고친 사례가 있으면 더 좋다.
- **통과:** 「이 부의 과제」의 완료 기준 여섯 가지를 모두 채웠다. 주소가 열리고 동작하며, 커밋과 되돌린 기록, 검산 기록, 인증키 없는 저장소가 확인된다.
- **보완:** 완료 기준 중 하나라도 빠졌다. 특히 주소가 평가자 휴대폰에서 열리지 않거나, 저장소에서 인증키·실제 고객 정보가 발견되거나, 원본 파일이 바뀌었으면 보완으로 돌려보내고 해당 단계(30·31·27단계)를 다시 하게 한다.

## 슬라이드 뼈대
### 슬라이드 1 · 제3부 Claude Code로 직접 만들기
- 『클로드 완전정복 100단계』 23~34단계
- 코드는 쓰지 않고, 맡기고 판단하는 법을 익힌다

### 슬라이드 2 · 윤서진 과장의 엑셀 네 개
- 메신저로 받은 방문 기록을 손으로 옮겨 적는 한 달
- 이 부가 끝나면 동료의 휴대폰에서 열리는 방문 일지를 넘긴다

### 슬라이드 3 · 세 도구의 역할
- Claude Code는 내 폴더에서 파일을 만들고 고치고 실행한다
- GitHub는 파일과 바뀐 기록을 보관하고, 배포 서비스는 그것을 인터넷 주소로 연다

### 슬라이드 4 · 첫 도구 고르기
- 틀리면 다시 입력하면 되는가, 공개돼도 되는 정보인가
- "누가, 언제, 어떤 화면에서, 무엇을 하려고 쓴다"로 적고, 더 붙일 것은 따로 모아 둔다

### 슬라이드 5 · 설치 전 준비
- 유료 계정, 터미널의 `pwd`·`cd`·`ls`
- 영문 이름, 공백 없음, 동기화 폴더 밖. 회사 PC는 먼저 묻는다

### 슬라이드 6 · 설치와 첫 실행
- 설치 명령은 공식 문서에서 복사하고 마지막 줄 안내를 읽는다
- 작업 폴더에 먼저 들어간 뒤 `claude`. 허락 요청은 하나씩 읽고 누른다

### 슬라이드 7 · CLAUDE.md와 계획
- 두 번 말한 규칙은 확인할 수 있는 문장으로 CLAUDE.md에 적는다
- 여러 파일에 걸친 일은 계획부터 받고 목적, 파일 목록, 지우기·덮어쓰기를 본다

### 슬라이드 8 · 자주 쓰는 / 명령어
- 새 과제는 `/clear`, 길어지면 `/compact`, 잘못 갔으면 `/rewind`
- 목록이 다르면 `/help`와 공식 문서가 맞다

### 슬라이드 9 · 코딩 없이 쓰는 Claude Code
- 원본·작업·결과 폴더, 원본은 사본만 넣고 읽기만 한다
- 합치기 전에 대응표, 받은 숫자는 건수·합계·빈 값으로 검산한다

### 슬라이드 10 · GitHub 첫 저장소
- 개인 계정, 비공개, README 없이 만든다
- 올릴 파일 목록부터 받고, 토큰은 내가 직접 넣는다

### 슬라이드 11 · 커밋·푸시·되돌리기
- 커밋은 이름표, 푸시는 보내기. 한 커밋에 한 가지를 우리말로
- 되돌리기는 기록을 새로 쌓는다. 강제로 덮어쓰기는 거절한다

### 슬라이드 12 · 배포
- 저장소 접근은 이 저장소 하나만 허용한다
- 배포는 동료가 자기 휴대폰으로 열었을 때 끝난다. 공개 범위는 배포 전에 거른다

### 슬라이드 13 · 배포가 멈출 때
- 화면이 그대로면 브랜치, 캐시, 로그 순으로 본다
- 로컬에서만 되면 로그, 환경변수 목록, 마지막 배포 시각 순으로 본다

### 슬라이드 14 · 안전장치
- 인증키는 환경변수에 두고 서버 쪽 함수가 쓰게 한다
- 읽기는 넓게, 쓰기는 좁게, 보내기는 확인 후에

### 슬라이드 15 · 훅·서브에이전트·MCP
- CLAUDE.md는 부탁, 훅은 장치. 어기면 되돌릴 수 없는 규칙만 훅으로
- 서브에이전트에는 좁은 역할을, MCP에는 좁은 권한을 준다

### 슬라이드 16 · 다 됐다는 말 나눠 읽기
- "추가했다"는 코드가 바뀌었다는 뜻이다. 화면에서 직접 눌러 본다
- 고친 것을 되돌려도 통과하는 테스트는 아무것도 증명하지 않는다

### 슬라이드 17 · 발표는 주소로 시작한다
- 열기, 한 문장, 한 동작, 한 사건
- 평가 기준: 열리는가, 동작하는가, 이어받을 수 있는가, 안전한가

### 슬라이드 18 · 제3부 과제
- 배포된 주소, 비공개 저장소, CLAUDE.md, 핵심 프롬프트 세 개
- 업무 파일 정리 결과와 검산 기록, 한 쪽짜리 메모
- 다음은 제4부 「Claude in Chrome, 브라우저를 맡기다」

## 자주 나오는 질문
**Q. 설치했는데 `claude`를 치면 "인식되지 않습니다"라고 나옵니다.**
A. 설치는 됐는데 터미널이 아직 모르는 상태다. 터미널을 닫고 새로 연 뒤 `claude --version`을 다시 친다. 그래도 안 되면 설치 마지막 줄에 나온 경로 안내를 다시 읽는다. 관리자 권한으로 억지로 밀어붙이지 말고 공식 문서의 안내대로 사용자 경로에 설치한다.

**Q. 보안 프로그램이 설치 스크립트를 막습니다. 잠깐 꺼도 될까요?**
A. 끄지 않는다. 회사 정책은 우회하지 말고 IT 담당자에게 무엇을 어디서 받아 무엇에 쓰는지 적어 보낸다. 24단계의 요청 메일 프롬프트를 쓰면 담당자가 예·아니오로 답할 수 있게 정리된다. 허락이 어렵다면 개인 노트북으로 연습한다.

**Q. CLAUDE.md에 적었는데도 규칙이 지켜지지 않습니다.**
A. 문장이 흐리거나 다른 규칙과 부딪히는 경우가 많다. "개인정보 조심"을 "거래처명, 사람 이름, 전화번호를 적는 항목이나 안내 문구를 만들지 않는다"처럼 확인할 수 있는 문장으로 바꾼다. 대화가 길어져 잊는다면 `/compact`나 `/clear`를 쓰고, 어기면 되돌릴 수 없는 규칙이라면 32단계의 훅 후보로 적는다.

**Q. 푸시할 때 "rejected"나 "non-fast-forward"가 뜨고, Claude가 강제로 덮어쓰자고 합니다.**
A. 저장소를 만들 때 README를 함께 만들었거나 GitHub 화면에서 직접 고쳐 양쪽 기록이 달라진 경우다. 강제로 덮어쓰지 말고 받아와 합치게 한다. 같은 줄을 양쪽에서 다르게 고쳐 충돌이 났다면 양쪽 내용을 나란히 보여 달라고 하고 남길 쪽은 내가 정한다.

**Q. 푸시했는데 주소의 화면이 그대로입니다.**
A. 먼저 배포 목록 맨 위의 새 배포가 본 주소로 나갔는지 본다. 미리보기로 표시돼 있으면 다른 브랜치에 있는 것이니 본줄에 합친다. 배포는 준비됨인데 내 화면만 예전이면 강력 새로고침이나 시크릿 창으로 연다. 배포가 실패로 끝났다면 로그를 열어 인증키로 보이는 값을 지우고 Claude Code에 붙여 원인을 묻는다.

**Q. 노트북에서는 되는데 배포한 주소에서는 데이터가 안 뜹니다.**
A. 로그, 배포 서비스의 환경변수 목록, 마지막 배포 시각 순으로 본다. `.env.local`에만 값을 넣고 배포 서비스에는 넣지 않았거나, 넣은 뒤 다시 배포하지 않은 경우가 흔하다. 파일 이름의 대소문자 차이도 배포 서버에서는 다른 파일로 취급될 수 있다.
