# 제4부 · Codex로 직접 만들기 — 강사용 안내

## 이 부의 목표
- ChatGPT의 Chat, Work, Codex가 각각 어떤 일에 맞는지 구분하고, 내 업무 다섯 가지를 셋 가운데 어디에 맡길지 정하게 합니다.
- Codex를 설치하고 회사 ChatGPT 계정으로 로그인한 뒤, AGENTS.md와 두 겹의 권한(샌드박스와 승인 정책)을 정하고 Git 체크포인트로 되돌리는 흐름을 익히게 합니다.
- 코딩 없는 파일 정리 한 건을 Codex로 처리하고, 클라우드에서 두 작업을 나란히 돌려 PR로 받고, GitHub의 `@codex review` 지적마다 판단을 남기게 합니다.
- Claude Code와 Codex가 서로 만든 것을 검토하는 교차 검토를 한 번 끝까지 해 보고, CLAUDE.md와 AGENTS.md의 공통 규칙을 같은 문장으로 맞추게 합니다.
- 39단계에서 제3·4부 결과물을 배포된 주소로 발표하고, 주소·저장소·두 규칙 파일·핵심 프롬프트·교차 검토 기록을 묶어 넘기며 제2편을 마무리합니다.

## 꼭 보여 줄 시연
1. **같은 요청, Chat과 Work (31단계).** 가상 분기 실적으로 "3장짜리 발표 자료를 만들어 줘"를 Chat과 Work에 한 번씩 넣습니다. 청중은 Chat은 대화 속 글로, Work는 미리 보고 내려받을 파일로 돌아오는 차이를 봅니다. 이어서 데스크톱 앱에서 ChatGPT와 Codex를 고르는 메뉴를 열어, 폴더와 코드를 다루는 일은 Codex로 간다는 점까지 보여 줍니다.
2. **API 키로 로그인했을 때 (32단계).** `codex login status`로 지금 로그인 방식을 보여 주고, API 키로 로그인하면 Codex cloud와 `@codex review`를 쓸 수 없고 요금이 따로 나간다는 점을 원고의 표로 설명합니다. 실제 키는 화면에 띄우지 않습니다. 이어서 Git이 없는 폴더에서 켜면 읽기 전용을 권하고, `git init`과 첫 커밋 뒤에 다시 켜면 Auto를 권하는 차이를 보여 줍니다.
3. **CLAUDE.md 규칙을 모르는 Codex (33단계).** CLAUDE.md만 있는 제3부 폴더에서 Codex를 켜고 "지금 따르고 있는 규칙을 요약해 줘"라고 묻습니다. CLAUDE.md의 규칙이 돌아오지 않는 장면을 보여 준 뒤, `/init`으로 AGENTS.md 초안을 받아 규칙을 옮기고 같은 질문을 다시 합니다. 작은 수정을 맡긴 뒤 `/diff`에서 시키지 않은 변경을 찾아 그 덩어리만 되돌리는 장면까지 이어 가면 좋습니다.
4. **건수가 안 맞는 합치기 (34단계).** 한 파일 맨 아래에 "합계" 줄과 빈 줄을 넣어 둔 CSV 서너 개로 합치기를 맡기고, 검산 프롬프트로 원본 줄 수의 합과 합친 표의 줄 수를 비교합니다. 청중은 "다 합쳤습니다"라는 보고와 실제 건수가 다를 수 있다는 점, 그리고 끝난 뒤 `git status`로 원본 폴더에 바뀐 파일이 없음을 확인하는 순서를 봅니다.
5. **리뷰 지적을 화면에서 재현하기 (36단계).** 미리 준비한 PR에 `@codex review`를 달아 👀 반응과 리뷰가 올라오는 것을 보여 줍니다. 지적 하나는 배포된 주소에서 직접 재현해 받아들이고, 우리 도구에 없는 기능을 문제 삼은 지적은 이유를 적어 반박한 뒤 `## Code Review Rules`에 규칙을 보탭니다. 리뷰에 시간이 걸릴 수 있으니 강의 전에 리뷰가 달린 PR을 하나 더 만들어 둡니다.
6. **교차 검토에서 갈린 의견 (38단계).** Claude Code가 만든 PR에 Codex 리뷰를 받고, 같은 변경을 Claude Code에게 "고치지 말고 보고만"으로 다시 검토하게 합니다. 두 결과를 나란히 놓고, 겹친 지적과 한쪽만 잡은 지적을 표로 나눕니다. 의견이 갈리는 항목은 화면에서 재현해 사람이 정한다는 점을 보여 줍니다.

## 과제 채점 기준
과제는 「제3부에서 만든 사내 도구를 Codex로 한 단계 넓히고, 두 에이전트의 교차 검토를 거쳐 배포하기」입니다.

| 항목 | 통과 기준 | 자주 보는 실수 |
|---|---|---|
| 배포된 주소 | 평가자가 자기 휴대폰으로 본줄 기준의 본 주소를 열고, 새로 넣은 기능을 도움 없이 끝까지 써 봅니다 | 미리보기 주소를 냅니다. 합친 PR이 본 주소에 아직 반영되지 않았습니다 |
| AGENTS.md와 CLAUDE.md | 두 파일이 저장소 맨 위에 있고, 공통 규칙 섹션이 글자까지 같습니다. AGENTS.md에 `## Code Review Rules`가 있습니다 | 한쪽 파일만 고쳐 날짜 형식 같은 규칙이 어긋나 있습니다. 리뷰 규칙이 "꼼꼼히 본다"처럼 가릴 수 없는 문장입니다 |
| Codex 리뷰 PR | 지적마다 받아들임·보류·반박·모름 가운데 하나와 이유가 댓글로 남아 있습니다 | 판단 없이 `@codex fix`로 바로 고치게 했습니다. 재현해 보지 않고 받아들였습니다 |
| 교차 검토 비교표 | Codex 리뷰와 Claude Code 검토가 각각 무엇을 지적했는지, 겹친 것과 한쪽만 잡은 것, 사람의 판단이 적혀 있습니다. 한쪽만 잡은 항목이 없었다면 없었다고 적었습니다 | 검토를 맡긴 쪽이 파일을 고쳐 버렸습니다. 두 결과를 합쳐 한 목록으로만 냈습니다 |
| 나눠 맡기기 | 두 작업이 겹치는 파일 없이 나뉘어 있고, 작업 하나에 PR 하나입니다 | 같은 화면 파일을 두 작업이 함께 건드려 충돌이 났습니다 |
| `codex exec` 점검 | 점검 명령과 결과 파일이 있고, 돌린 뒤 `git status`에 바뀐 파일이 없습니다 | `--sandbox workspace-write`를 붙여 점검이 파일을 고쳤습니다 |
| 안전 | 저장소, 커밋 기록, PR 댓글, 클라우드 환경 설정 어디에도 인증키·비밀번호·실제 고객 정보가 없습니다. 전부 허용 설정(`--yolo`, Full access)을 쓰지 않았습니다 | 클라우드 환경 변수에 키를 적었습니다. 편하다는 이유로 Full access를 켰습니다 |
| 한 쪽짜리 메모 | 어떤 일을 어느 에이전트에 맡기기로 했는지와 이유, 한 달 동안 기록할 항목(한도에 닿은 날, 교차 검토가 잡아낸 문제)이 있습니다 | "Codex가 더 좋다"처럼 기록 없이 도구의 우열을 적었습니다 |

**3단계 평가**
- **우수:** 모든 항목을 통과했고, 교차 검토 비교표에 한쪽만 잡은 항목과 그것을 화면에서 재현한 기록이 있습니다. 반박한 지적을 Code Review Rules로 옮긴 흔적이 있고, 메모의 한 달 기록 표에 첫 기록이 들어 있습니다.
- **통과:** 「이 부의 과제」의 완료 기준 여섯 가지를 모두 채웠습니다. 주소가 열리고 새 기능이 동작하며, 판단 없는 리뷰 지적이 없고, 두 규칙 파일의 공통 규칙이 같습니다.
- **보완:** 완료 기준 가운데 하나라도 빠졌습니다. 특히 인증키가 발견되거나, 공통 규칙이 어긋나 있거나, `codex exec` 점검이 파일을 바꿨다면 해당 단계(33·37·38단계)로 돌아가 다시 합니다.

39단계 발표는 과제와 따로 봅니다. 청중이 네 가지 기준(열리는가, 동작하는가, 이어받을 수 있는가, 안전한가)으로 예·아니오와 근거를 적고, 발표자는 지적받은 것을 다음 주 과제 목록에 올립니다.

## 슬라이드 뼈대
### 슬라이드 1 · 제4부 Codex로 직접 만들기
- 『클로드·GPT 완전정복 100단계』 31~39단계, 39단계에서 제2편 마무리
- 제3부의 습관을 그대로 들고 OpenAI의 Codex로 건너갑니다

### 슬라이드 2 · "다른 눈으로 본 적은 있어요?"
- 만든 쪽과 검토한 쪽이 같으면 같은 가정 안에서 봅니다
- 다른 회사가 만든 에이전트는 놓치는 곳도 다를 가능성이 큽니다
- 회사가 이미 ChatGPT를 쓴다면 새로 들일 것도 많지 않습니다

### 슬라이드 3 · Chat, Work, Codex
- 대화는 Chat, 검토할 결과물은 Work, 폴더와 코드는 Codex
- Claude로 치면 채팅, Cowork, Claude Code
- Work와 Codex는 요금, 크레딧, 사용량 한도를 함께 씁니다

### 슬라이드 4 · Codex를 쓰는 다섯 통로
- 데스크톱 앱, CLI, IDE 확장, Codex cloud, GitHub
- 어디까지 열리는지는 요금제와 로그인 방식이 정합니다
- 회사 자료는 회사 계정으로만

### 슬라이드 5 · 설치와 로그인
- 설치 명령은 공식 문서에서 복사하고 `codex --version`, 이상하면 `codex doctor`
- ChatGPT 계정 로그인이 기본. API 키 로그인은 따로 과금되고 클라우드를 못 씁니다
- `auth.json`은 비밀번호처럼 다룹니다

### 슬라이드 6 · 첫 폴더와 모델 고르기
- `git init`과 첫 커밋 뒤에 켜면 Auto를 권합니다
- 무언가 이상하면 먼저 `/status`
- 권장 추론 강도에서 시작하고, 답이 얕을 때만 한 단계씩 올립니다

### 슬라이드 7 · AGENTS.md
- 전역, 저장소 맨 위, 하위 폴더 순으로 이어 붙고 가까운 파일이 앞섭니다
- `/init`으로 초안을 받고 확인할 수 있는 문장으로 고칩니다
- Codex는 CLAUDE.md를 저절로 읽지 않습니다

### 슬라이드 8 · 두 겹의 울타리
- 샌드박스는 할 수 있는 범위, 승인 정책은 묻는 시점
- 평소는 Auto(`workspace-write` + `on-request`), 처음 보는 폴더는 읽기 전용
- 이름에 "위험하다"가 붙은 옵션은 쓰지 않습니다

### 슬라이드 9 · 되돌리기는 Git 체크포인트로
- Codex CLI에는 `/undo`도 `/rewind`도 없습니다
- 맡기기 전에 커밋, 끝나면 `/diff`로 확인한 변경만 남깁니다
- 데스크톱 앱 리뷰 화면에서는 덩어리 단위로 Revert

### 슬라이드 10 · 코딩 없이 쓰는 Codex
- 파일이 많고, 규칙이 되풀이되고, 변경 기록이 필요하면 Codex. 보고서 한 편은 Work
- 원본 복사본을 넣자마자 커밋, 살필 때는 읽기 전용
- 건수·합계·빈 값·`git status`. 합계 하나는 내 눈으로

### 슬라이드 11 · Local, Worktree, Cloud
- 지금 폴더, 떼어 낸 작업 공간, 클라우드 컨테이너
- 클라우드는 인터넷 Off로 시작하고 설치는 설정 스크립트에서
- 나누기 전에 파일 목록, 작업 하나에 PR 하나

### 슬라이드 12 · GitHub 리뷰를 Codex에게
- Code review를 켜고 PR 댓글에 `@codex review`
- 리뷰가 볼 기준은 AGENTS.md의 `## Code Review Rules`
- GitHub에는 P0·P1만 표시합니다. 지적이 없어도 화면은 직접 엽니다

### 슬라이드 13 · 지적은 사람이 판단한다
- 받아들임, 보류, 반박, 모름
- 가장 중요한 질문: 내가 화면에서 재현할 수 있는가
- 반박한 지적은 규칙으로 옮겨 되풀이되지 않게 합니다

### 슬라이드 14 · 설정·스킬·MCP
- 매번 고르던 것은 config.toml에, 되풀이하는 일은 스킬(`$이름`)에
- `/import`로 가져온 뒤에는 `/skills`, `/mcp`, `/hooks`를 직접 엽니다
- MCP는 읽기만 하는 연결부터, 회사가 허락한 것만

### 슬라이드 15 · `codex exec`
- 대화 없이 한 번 돌고 끝나는 명령, 기본이 읽기 전용
- `-o`로 결과를 파일에 남깁니다
- 자동으로 도는 일일수록 읽기 전용에서 시작합니다

### 슬라이드 16 · 어떤 일을 어디에 맡길까
- 규칙과 훅이 갖춰진 도구는 Claude Code, 겹치지 않는 작은 수정 여러 개는 Codex 클라우드
- 한쪽이 만든 변경의 검토는 만들지 않은 쪽
- 어느 쪽이 더 뛰어난지는 우리 팀 기록으로 정합니다

### 슬라이드 17 · 교차 검토의 세 규칙
- 검토하는 쪽에는 고치는 권한을 주지 않습니다
- 두 쪽에 같은 기준(공통 규칙)을 줍니다
- 의견이 갈리면 사람이 화면에서 재현합니다

### 슬라이드 18 · 규칙 파일 두 개
- 두 파일 맨 위에 같은 문장의 "공통 규칙"
- 고칠 때는 한 커밋에 함께, 한 달에 한 번 비교
- 오 차장의 날짜 형식 사건: 규칙을 다르게 준 쪽은 사람이었습니다

### 슬라이드 19 · 제2편 결과물 발표
- 열기, 한 문장, 한 동작, 한 사건
- 열리는가, 동작하는가, 이어받을 수 있는가, 안전한가
- 넘길 때는 주소, 저장소, 두 규칙 파일, 핵심 프롬프트, 교차 검토 기록

### 슬라이드 20 · 이 부의 과제와 다음 편
- 제3부 도구를 Codex로 넓히고 교차 검토를 거쳐 배포
- 제출물: 주소, 저장소, 두 규칙 파일, 리뷰 PR, 교차 검토 비교표, `codex exec` 점검, 한 쪽 메모
- 다음은 제3편, 제5부 「브라우저와 컴퓨터를 맡기다」

## 자주 나오는 질문
**Q. 데스크톱 앱에 Codex 메뉴가 없습니다.**
A. 앱이 오래됐거나 Free·Go 계정에 아직 열리지 않은 경우입니다. 앱을 최신으로 올린 뒤 다시 찾고, 그래도 없으면 요금제를 확인합니다. Free·Go는 데스크톱 앱에서만 Codex를 쓸 수 있고 계정마다 차례로 열린다고 원고에 적혀 있습니다. 회사 계정이면 관리자에게 Codex가 켜져 있는지 묻게 합니다(31·32단계).

**Q. 개발팀이 API 키를 줬는데, 그걸로 로그인해도 되나요?**
A. 되기는 하지만 권하지 않습니다. 쓴 만큼 개발팀 API 계정으로 청구되고, Codex cloud, `@codex review`, Slack 연동, 모바일 원격 제어를 쓸 수 없습니다. `codex login status`로 지금 방식을 보고, API 키로 되어 있으면 `codex logout` 뒤 `codex login`으로 회사 ChatGPT 계정에 다시 들어가게 합니다. 키를 쓴 사실은 준 사람에게 알리게 합니다(32단계).

**Q. AGENTS.md에 적은 규칙을 Codex가 모르는 것 같습니다.**
A. 세 가지를 차례로 봅니다. 다른 폴더에서 켰는지, 합친 크기가 한도(기본 32KiB)를 넘었는지, 하위 폴더에 `AGENTS.override.md`가 있어서 앞섰는지입니다. "지금 따르고 있는 규칙을 요약해 줘"라고 물어 확인하게 합니다. CLAUDE.md에만 적힌 규칙이라면 Codex는 기본으로 읽지 않으니 AGENTS.md에 같은 문장을 두게 합니다(33단계).

**Q. 매번 묻는 게 귀찮아서 Full access로 켜 두고 싶다고 합니다.**
A. 켜지 않게 합니다. 33단계 현장 장면처럼 승인 요청 하나가 원치 않는 설치를 막아 주기도 합니다. 평소에는 Auto로 두면 폴더 안의 일은 묻지 않고 하고, 폴더 밖을 고치거나 인터넷을 쓸 때만 묻습니다. 처음 몇 주는 Ask for approval로 두고 어떤 요청이 오는지 읽어 보는 편이 배우기에 좋다고 안내합니다. 회사에 따라 관리자가 `requirements.toml`로 이런 설정을 아예 막아 두기도 합니다.

**Q. 클라우드 작업이 "패키지를 설치하지 못해 테스트를 실행하지 못했습니다"로 끝납니다.**
A. 클라우드는 에이전트 단계에서 인터넷이 기본으로 막혀 있습니다. 인터넷을 켜기 전에 설치 명령을 설정 스크립트로 옮기게 합니다. 그래도 인터넷이 필요하면 Common dependencies와 읽기 메서드(GET, HEAD, OPTIONS)만 허용하는 데서 시작합니다. 시크릿은 설정 스크립트 단계에서만 쓰이고 에이전트 단계에서는 지워진다는 점도 함께 알려 줍니다(35단계).

**Q. 두 에이전트가 번갈아 가며 같은 부분을 바꿔 놓습니다.**
A. 두 규칙 파일의 내용이 다른 경우가 대부분입니다. 38단계의 두 번째 프롬프트로 CLAUDE.md와 AGENTS.md를 비교해 어긋난 규칙을 찾고, 두 파일 맨 위에 같은 문장의 공통 규칙 섹션을 둔 뒤 한 커밋에 함께 고치게 합니다. "두 파일을 함께 고친다"는 문장만으로는 모자라니 한 달에 한 번 비교하는 일을 달력에 넣게 합니다.

**Q. 교차 검토를 통과했는데 발표에서 흠이 나왔습니다. 교차 검토가 쓸모없는 건가요?**
A. 두 에이전트가 같은 규칙 문장을 기준으로 봤다면, 규칙에서 빠진 곳은 둘 다 보지 못합니다. 39단계 윤 과장 사례의 "화면에"라는 세 글자가 그렇습니다. 교차 검토는 확인의 겹을 하나 더할 뿐이고, 청중의 눈이 그다음 검토입니다. 흠이 나오면 규칙 문장을 넓혀 두 파일에 같은 문장으로 고치고, 꼭 지켜야 하는 규칙이면 훅 후보로 적게 합니다.

**Q. 두 구독이 부담스럽습니다. 둘 다 꼭 써야 하나요?**
A. 원고가 권하는 출발점은 한쪽을 주력으로 두고 다른 쪽은 검토용으로 가볍게 쓰는 것입니다. 한 달 동안 어느 쪽 한도에 먼저 닿았는지, 교차 검토가 무엇을 잡아냈는지 기록한 뒤 요금제를 조정하게 합니다. ChatGPT의 Work와 Codex는 한도를 함께 쓰니, 팀원이 Work로 보고서를 많이 만들면 Codex에 쓸 몫이 줄어든다는 점도 계산에 넣게 합니다(38단계).
