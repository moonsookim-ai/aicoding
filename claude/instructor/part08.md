# 제8부 · 회사 도구와 연결하기 — 강사용 안내

## 이 부의 목표

- 수강생이 자주 복사해 붙이던 사내 도구 두 곳을 골라 연결자로 연결하고, "목록 먼저, 요약은 고른 뒤"로 시험한 뒤 출처를 대조하게 합니다.
- 연결자가 하는 일을 읽기·쓰기·보내기 세 층으로 나누고, 보내기는 항상 사람이 누른다는 원칙을 팀 권한 표로 남기게 합니다.
- 연결이 막혔을 때 로그인, 관리자, 범위 순서로 원인을 좁히고, 관리자에게 범위와 원칙을 적은 요청서를 보낼 수 있게 합니다.
- ChatGPT·Codex를 쓰는 수강생에게는 같은 연결이 ChatGPT에서는 플러그인 속 앱(MCP 서버)으로, Codex에서는 `codex mcp add`나 `config.toml`로 붙는다는 점을 알려 줍니다. 규격이 같아 도구 목록 읽기와 권한 표는 그대로 씁니다.
- 이 부를 마치는 글의 제4편 결과물 발표에서 제6부의 스킬 하나와 연결자 둘로 돌아가는 업무를 보여 주고, 옆 사람이 그대로 쓸 수 있는 인수인계서를 만들게 합니다. 이 결과가 제9부 자동화의 첫 후보가 됩니다.

## 수업 시간표

65~69단계는 수강생이 회사에서 실제로 쓰는 도구를 다룬 두 단계를 골라 실습하고, 나머지는 강사가 요점만 설명합니다. 아래 시간은 원고의 **걸리는 시간**(읽기+따라 하기)을 그대로 더한 것이므로, 한 번의 수업으로 운영한다면 선택하지 않은 단계의 실습 시간은 빼고 계산합니다.

## 꼭 보여 줄 시연

1. **범위 없이 요약한 결과와 목록부터 받은 결과 비교(65단계).** 같은 주제로 "찾아서 요약해 줘"와 「복사해 쓰는 프롬프트」의 1단계를 나란히 돌립니다. 수강생이 볼 것은 목록에 찍힌 제목과 수정일 덕분에 초안·복사본·오래된 문서가 한눈에 걸러진다는 점입니다.
2. **도구 호출 펼쳐 보기(64단계).** 연결을 켠 대화에서 간단한 부탁을 하고, 답에 표시된 도구 호출을 펼쳐 어떤 도구를 불렀는지 보여 줍니다. 이어서 같은 연결자의 도구 목록을 읽기와 쓰기로 나눠 칠판에 적습니다. 수강생은 연결자를 이름보다 도구 목록으로 봐야 한다는 점을 알아차려야 합니다.
3. **결정으로 뽑힌 항목의 원문 확인(67단계).** 결정·미결·할 일·요청 네 가지로 받은 뒤, "결정" 하나를 눌러 원문을 엽니다. 반응 표시만 달린 제안이나 나중에 뒤집힌 결정이 섞여 있을 수 있다는 점을 보여 주고, 결정권자 조건을 넣은 프롬프트로 다시 돌립니다.
4. **확인 창 앞에서 멈추기(66·70단계).** 답장 초안을 받은 뒤 받는 사람·참조·첨부를 소리 내어 읽고, 보내기는 강사가 직접 누르거나 누르지 않고 끝냅니다. 문 상무 사례처럼 참조란 하나가 사고가 된다는 점, 확인 창에서 무엇을·어디에·누구에게를 읽는다는 점을 강조합니다.
5. **리허설 두 번의 차이(제4편 결과물 발표 준비).** "이번 주 보고 만들어 줘"로 한 번, 날짜 조건과 파일 목록 먼저 보기를 넣은 부탁으로 한 번 돌립니다. 수강생이 볼 것은 숫자가 틀린 것은 재료 문제, 항목이 흔들린 것은 형식 문제라는 구분입니다.
6. **같은 연결, ChatGPT와 Codex에서(64단계).** ChatGPT에서 Google Drive나 Gmail 플러그인을 켜고 입력창에 `@플러그인이름`을 붙여 65단계의 "목록 먼저" 프롬프트를 그대로 넣습니다. 이어서 Codex 쪽은 `codex mcp list`나 대화 중 `/mcp`로 등록된 MCP 서버 목록을 보여 줍니다. 수강생은 이름과 화면은 달라도 연결자를 도구 목록으로 읽고 "하지 않을 일"을 정하는 방식이 같다는 점, ChatGPT 웹은 내 컴퓨터의 로컬 MCP 서버를 읽지 않는다는 점을 봅니다. 회사 워크스페이스에서는 관리자가 플러그인을 막아 두었을 수 있으니 강사 계정에서 미리 확인합니다.

## 과제 채점 기준

과제 이름은 「연결자 둘과 스킬 하나로 돌아가는 업무 한 건」입니다.

| 항목 | 통과 기준 | 자주 보는 실수 |
|---|---|---|
| 권한 표 | 연결자마다 읽기·쓰기·보내기가 "열림/닫힘"으로 채워져 "모름"이 없습니다. 범위에서 뺀 공간과 항상 사람이 누르는 일이 적혀 있습니다 | "모름"을 남겨 둔 채 제출합니다. 보내기 층에 "급할 때는 자동" 같은 예외를 둡니다 |
| 검증 기록 | 연결자마다 출처 대조 세 건의 결과(맞음/틀림)와, 틀렸다면 고친 방법이 있습니다 | 요약만 받고 출처를 눌러 보지 않습니다. 틀린 건을 적고 고친 방법은 빠뜨립니다 |
| 인수인계서 | 업무 이름, 전에는, 쓰는 스킬, 쓰는 연결자, 부탁하는 말, 사람이 확인하는 단계, 넘겨받는 사람이 할 일이 한 페이지에 모두 있습니다 | 스킬 설치 방법이 빠져 동료가 돌리지 못합니다. 내 머릿속에만 있는 단계가 있습니다 |
| 결과물 세 벌 | 같은 부탁으로 세 번 돌린 결과가 같은 항목, 같은 순서이고 숫자와 사실이 원본과 맞습니다 | 세 번의 항목 순서가 다릅니다. 지난주 파일에서 숫자를 가져왔습니다 |
| 발표 | 전에는 → 실제로 돌리기 → 사람이 확인하는 단계, 세 부분이 모두 있고 현장에서 실제로 돌립니다 | 미리 만든 결과를 실제로 돌린 것처럼 보여 줍니다. 확인 단계를 말로만 넘깁니다 |
| 하지 않을 것 | 발표를 위해 보내기 권한을 열지 않았고, 회사 규칙이 허용하지 않은 자료를 범위에 넣지 않았습니다 | 시연을 매끄럽게 하려고 채널 게시나 메일 발송을 엽니다 |

| 수준 | 기준 |
|---|---|
| 우수 | 완료 기준 다섯 가지를 모두 채웠고, 동료가 인수인계서만으로 돌린 뒤 막힌 곳이 없었습니다. 결과물 세 벌의 날짜가 서로 다르고, 기밀 공간을 뺀 방법까지 권한 표에 적혀 있습니다 |
| 통과 | 결과물 세 벌이 같은 형식이고 원본과 맞습니다. 권한 표에 "모름"이 없고 보내기 층에 예외가 없습니다. 동료가 한 번 돌려 결과물을 얻었습니다 |
| 보완 | 권한 표에 "모름"이 남았거나, 결과물의 항목·순서가 흔들리거나, 동료가 인수인계서만으로는 돌리지 못했습니다. 71단계와 「제4편 결과물 발표」의 「막히면 이렇게」 표를 보고 다시 제출합니다 |

## 슬라이드 뼈대

### 슬라이드 1 · 제8부 회사 도구와 연결하기
- 『클로드·GPT 완전정복 100단계』 64~71단계, 마치는 글에서 제4편 결과물 발표
- 사람이 나르던 재료를 Claude가 직접 가져오게 합니다

### 슬라이드 2 · 사람이 거름망이 될 때
- 붙이는 순간의 사본은 낡습니다
- 바쁠수록 덜 붙이고, 출처는 흐려집니다
- 답이 틀렸을 때 거슬러 올라가면 재료가 원인인 경우가 많습니다

### 슬라이드 3 · 이 부의 흐름
- 64 원리, 65~69 도구별 연결, 70 경계, 71 막힐 때, 마치는 글에서 제4편 발표
- 65~69 가운데 우리 회사가 쓰는 두 단계를 골라 끝까지

### 슬라이드 4 · 연결자는 내 권한 안에서만 본다
- 내가 못 여는 폴더는 Claude도 못 엽니다
- 범위가 넓어 보이면 내 권한이 넓은 것
- 업로드, 연결자, Cowork, Claude in Chrome 고르는 표

### 슬라이드 5 · MCP는 콘센트 모양을 하나로
- 도구 열 개와 AI 세 개: 서른 번에서 열세 번으로
- 연결자를 볼 때는 이름보다 도구 목록
- 원격 커넥터와 데스크톱 확장
- ChatGPT는 플러그인 속 앱(MCP 서버)을 `@이름`으로, Codex는 `codex mcp add`와 `config.toml`로

### 슬라이드 6 · IT 요청서에는 하지 않을 일까지
- 오 본부장 사례: 조회만 원했는데 주문 입력이 들어왔습니다
- 누가 만들었나, 어떤 도구인가, 쓰기를 끌 수 있나

### 슬라이드 7 · 문서 창고: 목록 먼저
- 회사 계정인지부터 확인
- 목록(제목·위치·수정일) → 고른 문서만 요약 → 출처 대조
- 팀 약칭도 함께 알려 줍니다

### 슬라이드 8 · 메일과 일정: 보내기는 사람이
- 오늘 할 일 세 부분
- 검증은 "참고만" 쪽에서
- 틀린 분류는 프롬프트에 기준 한 문장

### 슬라이드 9 · 메신저: 요약 대신 결정을 묻는다
- 결정, 미결, 할 일, 나에게 온 요청
- 누가 말했나, 어떻게 동의했나, 뒤집히지 않았나, 채널 밖은 아닌가
- 인사·보상 채널과 개인 메시지는 뺍니다

### 슬라이드 10 · 업무 도구: 기준표가 곧 품질
- 이름보다 경계 문장
- 팀원 둘이 따로 분류하고 엇갈린 건에서 경계를 뽑습니다
- 대조 → 제안 → 좁은 쓰기, 발송·환불·닫기는 사람

### 슬라이드 11 · GitHub를 경영의 말로
- 저장소, 커밋, 이슈, Pull Request
- 리더가 볼 단위는 합쳐진 PR
- 연습은 공개 저장소로

### 슬라이드 12 · 읽기, 쓰기, 보내기
- 읽기는 넓게, 쓰기는 좁게, 보내기는 사람이 마지막에
- 성공이 쌓일수록 확인이 느슨해집니다
- 확인 창: 무엇을, 어디에, 누구에게

### 슬라이드 13 · 팀 권한 표 만들기
- 연결자마다 세 층을 열림/닫힘으로
- "모름"은 하루 안에 확인
- 이 표가 제11부 운영 규칙의 초안
- ChatGPT 워크스페이스라면 관리자의 Workspace apps 설정과 맞춰 봅니다

### 슬라이드 14 · 연결이 안 될 때
- 로그인 만료 → 관리자 승인 → 권한 범위
- "찾지 못했다"는 빈 답이면 연결부터 의심
- 관리자에게는 편의 대신 범위와 원칙을

### 슬라이드 15 · 제4편 결과물 발표
- 좋은 과제: 반복, 재료 두 곳 이상, 형식이 정해짐
- 전에는 → 실제로 돌리기 → 사람이 확인하는 단계
- 옆 사람에게 넘겨서 돌아가면 시스템

### 슬라이드 16 · 흔들릴 때 나누어 보기
- 숫자가 틀리면 재료 문제
- 항목이 흔들리면 형식 문제
- 임 팀장의 네 번 리허설

### 슬라이드 17 · 이 부의 과제
- 연결자 둘과 스킬 하나로 돌아가는 업무 한 건
- 제출물: 권한 표, 검증 기록, 인수인계서, 결과물 세 벌, 발표
- 하지 않을 것: 보내기 권한 열기, 허용 안 된 자료 넣기, 미리 만든 결과 보여 주기

### 슬라이드 18 · 다음 부 예고
- 제9부는 자동화
- 세 번 같은 형식으로 나온 업무가 첫 후보
- 보내기 앞에는 사람이 있다는 원칙은 그대로 갑니다

## 자주 나오는 질문

**Q1. 설정에 연결자 항목 자체가 안 보입니다.**
요금제나 조직 관리자 설정 때문인 경우가 많습니다. 공식 안내에서 요금제별 제공 여부를 보고, 팀 요금제라면 관리자에게 묻습니다. 어느 요금제에서 무엇이 열리는지는 자주 바뀌므로 수업에서 목록을 단정하지 않습니다(64단계).

**Q2. 분명히 있는 문서인데 Claude가 "찾지 못했다"고 합니다.**
개인 계정으로 연결됐거나, 공유 드라이브나 공유받은 문서가 검색 범위 밖일 수 있습니다. 연결된 계정을 먼저 확인하고, 파일 이름의 핵심 낱말이나 폴더 이름을 그대로 알려 줍니다. 모든 요청이 빈 답이라면 로그인 만료를 의심해 연결을 끊었다가 다시 연결합니다(65·71단계).

**Q3. 연결자 설명만으로는 쓰기 도구가 있는지 모르겠습니다.**
연결을 켠 대화에서 "이 연결자로 할 수 있는 일을 읽기와 쓰기로 나눠 알려 줘"라고 묻고, 제공처의 안내와 맞춰 봅니다. 권한 표에서 "모름"으로 남기지 말고 하루 안에 확인하게 합니다(64·70단계).

**Q4. Slack 연결 중에 관리자 승인이 필요하다고 나옵니다.**
내 쪽에서 풀 방법은 없습니다. 화면을 캡처해 두고, 71단계 프롬프트로 업무·필요한 범위·제외할 범위·지키는 원칙을 적은 요청서를 만듭니다. 데이터 보관처럼 Claude가 단정할 수 없는 내용은 "공식 안내 확인 필요"로 두고 공식 문서 링크를 붙입니다.

**Q5. 메신저에서 제안이 결정으로 뽑힙니다.**
결정의 기준을 주지 않아서입니다. 프롬프트에 결정권자 이름과 "동의한 것만 결정으로 본다", "반응 표시만 있는 것은 애매함"을 넣습니다. 결정이 회의나 통화에서 났다면 Claude로는 풀 수 없으니, 회의 뒤 결정을 채널에 짧게 적는 팀 규칙을 만듭니다(67단계).

**Q6. 발표 도중 연결이 끊기면 어떻게 합니까?**
미리 받아 둔 결과 화면으로 넘어가고, 끝난 뒤 원인을 적습니다. 발표 직전에 두 연결자가 간단한 요청에 응답하는지 확인하는 것이 먼저입니다. 다만 준비한 화면을 실제로 돌린 것처럼 보여 주지는 않습니다(71단계).

**Q7. ChatGPT나 Codex를 쓰는 수강생은 어디서 연결하나요?**
ChatGPT에서는 연결 기능이 플러그인 안에 있습니다. Google Drive, Gmail, Slack, GitHub, SharePoint 같은 서비스를 플러그인 속 앱으로 연결하고 입력창에서 `@플러그인이름`으로 부릅니다. 목록에 없거나 Developer mode 메뉴가 안 보이면 워크스페이스 관리자가 막아 둔 경우가 많으니 71단계와 같은 요청서를 보냅니다. Codex는 `codex mcp add`로 등록하거나 `~/.codex/config.toml`에 적고, 로그인이 풀리면 `codex mcp login <이름>`으로 다시 로그인합니다. ChatGPT 웹은 로컬 MCP 서버를 읽지 않으니 안 보이는 것이 고장은 아니라고 알려 줍니다. 보내기는 어느 도구든 사람이 누릅니다(64·70·71단계).
