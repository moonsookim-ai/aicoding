# 제8부 · 알아서 돌아가게 만들기 — 강사용 안내

## 이 부의 목표

- 규칙이 분명하고 틀려도 되돌릴 수 있는 업무를 골라, 손으로 한 순서를 여섯 줄 설계로 옮기게 한다.
- 시작 신호(시각·새 메일·새 파일·버튼)를 고르고, Cowork 예약 작업과 외부 자동화 도구로 저절로 도는 흐름을 하나 끝까지 잇게 한다.
- 흐름에 세 가지 장치를 붙이게 한다. 밖으로 나가기 전의 승인 단계, 조용한 실패를 알리는 알림, 한 달 실행 횟수 × 1회 비용 계산표.
- 부서의 반복 업무를 자동화 지도로 그리고, 모든 흐름에 주인 한 명과 대신 볼 사람 한 명의 이름을 붙이게 한다.

## 수업 시간표

시간은 원고의 **걸리는 시간**(읽기+따라 하기)을 더한 것이다. 75~76단계는 외부 자동화 도구 계정과 API 키가 필요하므로, 수업 전에 도구 사용 가능 여부와 회사 데이터를 태워도 되는지를 수강생에게 미리 확인하게 한다.

| 순서 | 단계 | 시간(분) | 방식 | 요점 |
|---|---|---|---|---|
| 0 | 도입 | 10 | 설명 | 제5부 스킬과 제7부 연결자 복습, 사람이 서는 세 곳(처음·승인·점검) |
| 1 | 71단계 · 자동화할 일, 하지 말아야 할 일 | 30 | 설명·실습 | 규칙과 되돌림 두 기준, 네 경우 표, 하지 말 일 목록 |
| 2 | 72단계 · 손으로 한 순서가 곧 설계도다 | 50 | 설명·실습 | 여섯 줄, 몸에 밴 판단 찾기, 기계에 넘길 줄과 사람이 맡을 줄 |
| 3 | 73단계 · 트리거: 언제 시작할 것인가 | 25 | 설명·실습 | 네 가지 시작 신호, 사건 트리거의 조건, 몰리는 날 계산 |

| 11 | 정리 | 10 | 설명 | 「제8부를 마치며」 일곱 항목 점검, 과제 안내, 제9부 예고 |
| | 합계 | 510 | | 두 번 이상의 수업으로 나누는 편이 안전하다(71~74 / 75~80) |

## 꼭 보여 줄 시연

1. **한 문장 설계와 여섯 줄 설계의 결과 비교(72단계).** "실적 자료를 모아 요약해서 보낸다"로 한 번, 기간·반품 제외·미제출 표시를 넣은 여섯 줄로 한 번 돌린다. 수강생이 볼 것은 첫 결과가 멀쩡해 보이지만 기간과 합계가 틀렸다는 점, 그리고 그 판단은 손으로 해 본 사람만 안다는 점이다.
2. **예약 전에 지금 한 번 돌리기(74단계).** 샘플 폴더로 보고서를 한 번 만들고 숫자 둘을 원본과 대조한 뒤, 기간을 데이터가 없는 주로 바꿔 메모가 저장되는지 보여 준다. 그다음에야 예약한다. 수강생은 예약 작업이 되물을 수 없어서 지시문에 기간·예외·저장 이름을 미리 넣어야 한다는 점을 알아차려야 한다.
3. **흐름 속 지시문의 출력 모양(75단계).** 앱에서 쓰던 식의 지시로 샘플 세 건을 돌려 출력 모양이 제각각인 것을 보여 주고, "너는 자동화 흐름의 한 단계다"와 세 줄 출력 형식을 넣은 지시로 다시 돌린다. 빈 입력이 "확인필요"로 나오는 것까지 확인한다. API 키는 화면에 전체 값이 보이지 않게 가린다.
4. **메일 한 통이 시트 한 행이 되기까지(76단계).** 샘플 메일 네 통(평범한 문의, 환불 요구, 한 문장 메일, 긴 인용 답장)을 차례로 보내고 시트와 채널 알림을 함께 띄운다. 인용 답장의 요약이 옛 내용을 말하는지, 환불 초안에 "[담당자 확인 필요]"가 남는지를 수강생과 함께 본다.
5. **일부러 실패시키기(78단계).** 원본 파일 이름을 잠시 바꿔 흐름을 돌리고, 두 사람에게 실패 알림이 가는지, 결과 대신 "읽지 못함" 메모가 남는지 보여 준다. 에러가 안 났어도 내용이 틀릴 수 있다는 점을 결과 속 건수로 설명한다.

## 과제 채점 기준

과제 이름은 「저절로 도는 흐름 하나와 그 운영 서류」다. 실습 중에는 회사 기밀이나 고객 개인정보가 없는 샘플 자료를 쓰고, 실제 자료에 붙이기 전에 회사 규정과 IT 담당의 확인을 받았는지도 함께 본다.

| 항목 | 통과 기준 | 자주 보는 실수 |
|---|---|---|
| 여섯 줄 설계서 | 첫 줄에 받는 사람과 쓰임새가 있고, 손으로 할 때 찾아낸 판단이 규칙으로 들어 있다. "누가 보는가"에 무엇을 대조하는지가 있다 | "보고서를 만든다"처럼 첫 줄이 비어 있다. 판단 없이 순서만 적었다 |
| 흐름 그림 | 시작 신호부터 보관까지 단계가 순서대로 있고, 단계마다 "자동화" 또는 "사람" 표시, 승인 단계와 실패 알림의 위치가 보인다 | 승인 단계를 말로만 적고 그림에는 없다. 실패 알림이 어디 붙는지 빠졌다 |
| 실행 기록 | 정해진 때 돈 결과물이 세 번 이상 있고, 결과마다 읽은 원본 건수와 사람이 대조한 숫자 표시가 있다 | 손으로 돌린 결과를 섞어 낸다. 건수가 없어 평소와 비교할 수 없다 |
| 비용 계산표 | 한 달 실행 횟수, 몰리는 날 횟수, 1회 사용량, 1회 비용, 한 달 비용과 요금표를 본 날짜가 있다 | 실행 횟수를 짐작으로 적는다. 요금을 기억이나 Claude의 답에서 가져온다 |
| 부서 자동화 지도 | 80단계 항목이 채워져 있고, 이번 흐름이 첫 행에, 다음 업무 하나에 주인과 날짜가 있다 | 담당자 란에 팀 이름을 적는다. 위험 판정에 이유가 없다 |
| 안전 조건 | 승인 없이 보내기·결제·삭제하는 단계가 없고, 일부러 실패시켰을 때 두 사람 이상이 알림을 받았으며, 자료가 없을 때 "없음" 메모가 남는다 | 시험 중에 만든 곧바로 보내는 단계가 남아 있다. 알림이 본인 한 명에게만 간다 |

| 수준 | 기준 |
|---|---|
| 우수 | 완료 기준 다섯 가지를 모두 채웠고, 멈췄을 때의 절차가 흐름 설명 옆에 있어 만든 사람이 아닌 동료도 흐름을 끄고 다시 돌릴 수 있다. 첫 달 실제 사용량을 계산표와 비교한 기록까지 있다 |
| 통과 | 흐름이 사람이 누르지 않아도 세 번 이상 돌았고, 승인 없는 보내기 단계가 없으며, 실패 알림이 두 사람에게 가고, 흐름에 주인과 대신 볼 사람의 이름이 있다 |
| 보완 | 흐름이 세 번 돌지 않았거나, 승인 없이 밖으로 나가는 단계가 남았거나, 실패 알림·"없음" 메모 가운데 하나가 없다. 해당 단계(74·77·78단계)의 「막히면 이렇게」를 보고 다시 제출한다 |

## 슬라이드 뼈대

### 슬라이드 1 · 제8부 알아서 돌아가게 만들기
- 클로드 완전정복 100단계, 71~80단계
- 첫마디를 시간과 사건에 넘긴다

### 슬라이드 2 · 사람은 빠지지 않고 서는 곳이 바뀐다
- 무엇을 돌릴지 정하는 처음
- 밖으로 나가기 직전의 승인
- 멈췄을 때 알아채는 점검

### 슬라이드 3 · 두 흐름을 끝까지
- 설계의 여섯 줄: 얻으려는 것, 재료, 지시, 결과, 보는 사람, 받는 사람
- 기계의 여섯 단계: 새 메일, 꺼내기, 넘기기, 분류·요약, 기록·알림, 보관

### 슬라이드 4 · 무엇을 자동화하나
- 규칙이 분명한가, 틀려도 되돌릴 수 있는가
- 바로 자동화, 초안까지만, 맡기고 확인, 자동화 안 함
- 시간이 많이 드는 일과 자동화하기 좋은 일은 다르다

### 슬라이드 5 · 하지 말 일의 목록
- 기밀, 개인정보, 사람 평가, 돈, 법적 책임
- 팀 문서 맨 위에 붙여 둔다

### 슬라이드 6 · 손으로 한 순서가 설계도
- 머릿속 순서와 실제 순서는 다르다
- 첫 줄에 받는 사람과 쓰임새
- 보는 사람 줄에는 무엇을 대조하는지

### 슬라이드 7 · 트리거 네 가지
- 시각, 새 메일, 새 파일, 버튼
- 처음에는 시각 트리거로
- 사건 트리거에는 조건, 몰리는 날 계산

### 슬라이드 8 · 예약은 맞은 지시만
- 지금 한 번 돌리고 대조한 뒤 예약
- 기간·예외·저장 이름을 지시문에
- 예약 작업은 저장까지만

### 슬라이드 9 · 외부 도구 속 Claude
- Zapier, Make, n8n에서 한 단계로
- Claude Console: 결제 → 한도 → 키 → 시험
- API 키는 비밀번호, 흐름마다 따로

### 슬라이드 10 · 흐름 속 지시문
- 되물을 수 없다: 모르면 "확인필요"
- 출력 모양을 못 박고 다른 말은 붙이지 않는다
- 확신 항목으로 볼 건을 줄인다

### 슬라이드 11 · 메일 한 통이 시트 한 행으로
- 여섯 단계 표와 "여기서 끊기면"
- 인용된 이전 메일은 무시
- 보내기 단계는 만들지 않는다

### 슬라이드 12 · 마지막 버튼은 사람이
- 팀 밖에 닿는가, 돈이나 권리가 움직이는가, 되돌릴 수 있는가
- 상태 열, 채널 확인, 초안으로 남기기, 권한 좁히기

### 슬라이드 13 · 승인이 형식이 되지 않게
- 느슨한 알림과 좁힌 알림
- 확인할 곳을 초안 안에 표시
- 승인자는 두 명 이상

### 슬라이드 14 · 조용한 실패
- 에러가 없어도 빈 결과일 수 있다
- 도구 알림, 빈 결과 메모, 정기 점검을 겹친다
- 결과 속 건수를 평소와 비교

### 슬라이드 15 · 멈춘 뒤의 순서
- 끈다 → 언제부터인지 찾는다 → 고치고 다시 돌린다 → 기록한다
- 원본은 일정 기간 남겨 둔다

### 슬라이드 16 · 비용은 곱셈 하나
- 한 달 실행 횟수 × 1회 비용
- 요금은 공식 요금표에서, 사용량은 실제로 재서
- 보내는 글, 모델, 묶음, 조건으로 줄인다

### 슬라이드 17 · 부서 자동화 지도
- 효과 크고 위험 낮은 일부터
- 옆 팀의 흐름부터 확인
- 모든 자동화에 사람 이름, 분기마다 다시 연다

### 슬라이드 18 · 이 부의 과제
- 저절로 도는 흐름 하나와 그 운영 서류
- 여섯 줄 설계서, 흐름 그림, 실행 기록, 비용 계산표, 자동화 지도
- 승인 없는 보내기 없음, 두 사람 알림, "없음" 메모, 주인 이름

### 슬라이드 19 · 다음 부 예고
- 제9부는 새 도구 없이 부서 업무에 대 본다
- 계획을 먼저 읽고, 되돌릴 수 있게 하고, 직접 돌려 본다

## 자주 나오는 질문

**Q1. 가장 귀찮은 일이 "자동화 안 함"으로 나왔습니다. 그래도 하고 싶습니다.**
귀찮음은 판단이 많다는 신호다. 그 일 안에서 판단이 없는 앞부분, 이를테면 자료 모으기와 표 만들기만 떼어 후보로 삼는다. 동그라미가 하나도 없다면 업무를 너무 크게 적은 것이니 "월말 결산"을 "카드 내역 모으기"처럼 쪼갠다(71단계).

**Q2. 예약해 두었는데 월요일에 파일이 생기지 않았습니다.**
컴퓨터가 꺼져 있었거나 앱이 닫혀 있었을 가능성이 가장 크다. 컴퓨터가 켜져 있는 시각으로 예약을 옮기고, 도는 조건은 공식 도움말에서 확인한다. "자료를 읽지 못함" 메모만 있다면 연결자 로그인 만료나 원본 파일 이름 변경을 본다(74단계).

**Q3. API 키를 만들었는데 호출이 실패하고, 키를 다시 볼 수도 없습니다.**
콘솔의 결제·한도·사용량 화면을 차례로 확인한다. 키 전체 값은 만들 때 한 번만 보여 주므로, 다시 볼 수 없는 키는 폐기하고 새로 만들어 바로 외부 도구의 연결 설정에 넣는다. 흐름마다 키를 따로 두고 흐름 이름을 키 이름에 붙이게 한다(75단계).

**Q4. 시트의 한 셀에 문장이 통째로 들어갑니다.**
출력 모양을 정하지 않아서다. 항목 이름과 순서를 못 박고 "다른 말이나 꾸밈 기호는 붙이지 않는다"를 넣는다. 그래도 흔들리면 예시 출력을 하나 보여 준다. 엉뚱한 입력에도 억지로 분류가 붙으면 "확인필요"와 확신 항목을 둔다(75단계).

**Q5. 승인자가 읽지 않고 누르는 것 같습니다.**
알림이 "승인해 주세요"뿐이라 볼 곳이 넓어서다. 수량·단위·받는 곳처럼 확인할 것 두세 가지를 알림에 바로 보이게 하고, 초안에 확인 필요 표시를 넣는다. 한 달 뒤 틀린 샘플을 한 번 섞어 승인 단계에서 돌아오는지 확인하는 방법도 있다(77단계).

**Q6. 월말 사용량이 계산보다 크게 나왔습니다.**
긴 입력이나 몰리는 날을 계산에 넣지 않았거나, 재시도와 시험 실행이 빠졌을 수 있다. 긴 샘플로 다시 재고 몰리는 날 횟수를 따로 넣는다. 같은 사람이 다시 보낸 메일처럼 새로 돌 필요가 없는 건은 조건으로 뺀다(79단계).
